# Local model usage

Issue #47 adds a settings page for provider-reported tokens and observed outbound requests by local date, requested model and retained feature. The default metric remains input tokens, and every saved model is visible initially. Compact 7-day / 30-day / custom range controls sit opposite the metric selector. A single themed card contains the summary, continuous stacked date chart and model filters. It follows the reference screen's spacing and visual hierarchy without adding a chart dependency.

Dates share a zero-based scale over the entire selected period, including graph pages of up to 31 dates. Clicking a date or model segment selects the same scope for the summary, feature table and shares. The chart has one Tab stop; arrows, Home and End move date focus, and Enter/Space select. After selecting a date, named model buttons offer a keyboard/touch path to zero, unreported and very small segments. Segment heights have no artificial minimum. Colors, patterns and collision aliases use the entire saved model list, independently of date filters and visibility. Service/model labels contain no transport jargon or hash fragments; duplicate connections get numbered aliases, while arbitrary custom names remain unavailable. Recreated connections can have a different alias because user connection names are not collected.

The feature table shows only features with observed dispatches or finished results, including measured zero and unreported tokens. Its default columns are feature, selected metric and share; Details reveals input/output tokens and requests. Shares use the same filtered reported-value denominator as the summary; unknown rows and a zero denominator show an unavailable share, never a guessed zero percent. Partial/mixed reporting is marked as reported values only. Dates without observations are not asserted to have measured zero tokens, and saved date keys remain authoritative rather than reinterpreting the observation timestamp in a new timezone. Necessary number/date/persistence caveats live in a compact collapsed help section. The original cumulative request comparison remains under All-time requests, with service labels instead of internal transport names. English, Korean and Japanese strings are localized; the seven restored locales use documented English fallback for this page.

## Observations and dates

- A request is a provider `fetch` dispatch, not queue admission, a cache lookup, a stream chunk, server acceptance or successful output. Retries, fallbacks and provider transport subrequests/polling count when dispatched. One batch fetch counts once. Cache hits, deduplicated followers and cancellation before dispatch do not count. Dispatched attempts stay counted after failure/cancellation.
- Requests use the device's local civil date at dispatch. Token observations use the local civil date when the finished generation is observed. A request dispatched before midnight and completed after midnight can have its request and tokens on different dates. These are observation dates, not inferred upstream billing dates.
- Date keys are fixed `YYYY-MM-DD` labels determined before asynchronous storage work. A timezone/clock change affects subsequent observations only; saved buckets are not regrouped. A repeated civil date accumulates into the existing bucket. Calendar range arithmetic is independent of DST. Formatting a saved civil date does not convert it to a different timezone date.
- History starts with the first observation from this version, including its timestamp. The first day is partial from that time. Earlier lifetime counts are never distributed into dates/models or converted into token estimates. Entire periods before history begins are unavailable, not a zero table; overlapping periods show recorded values with an explicit earlier-history warning.

Retained features are page translation (including titles), selected-text translation, video subtitles, dictionary, sentence explanation, custom AI actions, reading/note suggestions, page/subtitle context summaries, video summary, AI subtitle segmentation and AI language detection. Missing/future/invalid telemetry tags use the shared category without rejecting otherwise valid inference payloads. Mixed batches retain their existing grouping and get one shared count. Labels are excluded from batch/cache/dedup identities. Authentication, refresh, model discovery, connection checks, subtitle downloads and removed features remain outside this dashboard.

## Token availability and coverage

Only supplied numeric usage is retained. `inputTokens` and `outputTokens` are the installed AI SDK 7 provider-normalized totals; the dashboard does not add cache/reasoning counts to them again. Missing/malformed values are unavailable. When an SDK adapter defaults a missing raw field to zero, the zero is not treated as measured without an explicit source token field. Genuine source zeros remain measurable. Conservative availability checks can leave unsupported zero shapes unreported.

The BYOS service reads optional numeric usage only from its existing valid `response.completed` event. It does not make additional requests, estimate from characters or alter its admission, generation, cancellation, completion, refusal, size or non-retryable stream guards. The adapter exposes those numbers to the SDK when supplied; absence retains the previous undefined usage. Token metadata from a truncated/unaccepted stream is not invented or promoted to a completed result.

Input/output reporting coverage is counted separately against finished local generation results, including failures/cancellation. It is not HTTP-attempt coverage: one generation can make several dispatches, and failed/intermediate attempts may consume tokens that are not observable. A full result-coverage ratio therefore does not establish full upstream consumption. Totals with missing result reports are marked partial; zero reports render **Unreported**, not numeric zero. Error paths without accessible final usage remain unreported. Provider-reported numbers are diagnostics, not costs, billing totals or subscription quota. No total-token metric is calculated by filling a missing input/output dimension with zero.

Source checks for the installed versions:

- AI SDK `src/types/usage.ts` reads V4 input/output totals and derives its total field from those dimensions. The dashboard uses the two dimensions independently.
- OpenAI `responses/convert-openai-responses-usage.ts` already includes cached/cache-write input in `input_tokens`; reasoning is part of `output_tokens`.
- Anthropic `convert-anthropic-usage.ts` normalizes cache read/write into its input total under its provider-specific rules. Google `convert-google-usage.ts` normalizes prompt/tool input and candidate/reasoning output; missing-field zero fallbacks require care.
- The [official Responses completion event](https://developers.openai.com/api/reference/resources/responses/streaming-events) defines optional response usage, and [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) places cached tokens inside input usage. This is evidence for the response shape, **not a verified guarantee that every BYOS subscription response supplies usage**. Live BYOS availability has not been tested in this delegated task.

## Identity, privacy and retention

`local:apiUsageV1` remains unchanged: original fixed feature API/BYOS counters and first counting timestamp. `local:apiUsageHistoryV1` is a separate versioned record with first observation timestamp, safe model descriptors and sparse date → model → feature numeric aggregates. Each feature cell stores dispatch count, finished-result count, known input/output report counts and sums. Internal sum zero plus report count zero means unavailable and is never shown as measured zero.

Identities follow the captured requested provider/model configuration. Provider type, API/BYOS transport and an opaque configured-row alias distinguish equal model names; BYOS groups its shared subscription bridge by model without account identifiers. Upstream routing/fallback models are not reconstructed. Only code-owned public model IDs or a restricted public OpenAI model grammar can be saved as labels. Arbitrary custom models get opaque aliases. User provider names, endpoints, headers, prompts, source/translated text, keys, OAuth tokens, credentials, account identifiers, error text and per-request journals are not stored or logged by this feature. Hashes use configured row/model identity, never credential or endpoint fields.

History is local, indefinite and sparse; no automatic deletion, reset, export or data migration/backfill is added. A compact illustrative dense cell set using all 13 features costs approximately 1.7 kB per active model/day at zero-valued counters, or 3.0 MB for five models active every day for a year before larger digits/descriptor overhead. Sparse real feature use is smaller. The existing `unlimitedStorage` permission is reused; no new permission is introduced. This is a capacity illustration, not a retention policy.

Lifetime and history have independent background persistence chains. Writes never delay network dispatch or consume/clone a stream. Failed writes retain pending deltas for retry; invalid/future data is preserved and reported unavailable. Snapshot reads flush prior pending writes and carry separate incomplete flags. Abrupt worker termination or storage failure can lose observations before writing, and the two stores have no network/storage transaction; their totals can differ when failures occur. The page states these diagnostic limits.

Model-less DeepL/DeepLX requests show the provider alone rather than a private-model alias. History validation rejects nonempty records without an observation start, positive tokens without their corresponding report count, and histories whose nonnegative metric aggregates exceed the safe integer range. Checking the whole stored history also bounds every filtered chart/table subset; validation runs before writes, so an overflowing update does not replace the existing stored record. These cases use the existing unavailable-history state and never reset either store.
