# Experimental BYOS status

BYOS means bring your own subscription. This integration candidate combines the reviewed browser-only ChatGPT stack through [PR57](https://github.com/aittaa/lingo-tori/pull/57), [PR41](https://github.com/aittaa/lingo-tori/pull/41)'s missing-Content-Type fix, and pinned independent main. See [integration preparation](byos-core-integration.md) for exact inputs and validation.

The owner approved honoring existing BYOS ON/OFF, saved models and feature assignments without a separate deactivation migration. Enabled BYOS rows can be selected for supported features; OFF rows and assignments are preserved and excluded from feature execution. Account/model management remains separate. Actual inference still requires validated credentials, account scope and model access in the private extension-origin vault. Configuration contains no BYOS tokens or API-key/endpoint fields. BYOK remains independent, with no automatic provider fallback.

Sign in is an explicit Firefox or Chromium action inside API Providers. Firefox now includes experimental callback routing, but real Firefox/OpenAI sign-in remains NOT RUN; see [Firefox authentication and acceptance](byos-firefox.md). The browser-storage/navigation-redirect design differs from current official listener/runtime guidance and is not established as officially supported or store-approved. No companion server, pairing key or service setup is restored. Read [BYOS architecture and user flow](byos.md).

Earlier PR41 live evidence verifies its tested initial Chrome translation flow only. It does not validate this newly combined tree. Integration preparation performs source/offline checks without real accounts, credentials, inference, browser operations or CI dispatch. Material integration changes remain subject to review and explicit merge approval. Use the [BYOK setup guide](byok.md) for the independent API-provider path.
